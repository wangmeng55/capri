# C4 · 流的取消、背压、超时与断线

## 1. 身份与状态机

hub 维护 Browser请求/认证会话 ↔ connId+reqId ↔ host流 的关联。host 维护 connId+reqId ↔ 本机HTTP请求/升级连接 的关联。所有回调必须检查仍属于当前请求，不能通过仅相同 reqId 找到重连后的新请求。

| 阶段 | 允许的事件 | 后续 |
|---|---|---|
| OPEN | http-open/ws-open、本机连接建立、request-data/end | HEADERS / UPGRADING / TERMINAL |
| HEADERS | 已取得普通最终响应头 | STREAMING / TERMINAL |
| STREAMING | response-data、独立窗口、request-stop | response-end 或 TERMINAL |
| UPGRADING | 本机拒绝HTTP响应，或合法101 | STREAMING（拒绝）/ UPGRADED / TERMINAL |
| UPGRADED | 双向ws-data/window-update/ws-end | 双向结束或 TERMINAL |
| TERMINAL | 正常结束、cancel、错误、连接断开 | 一次性清理，不再打开本机请求 |

本机的响应头已取得，与浏览器响应头已提交是两件事；hub 记录后者，决定错误时还能否写HTTP状态码。cancel 与正常结束可以竞争；清理以原子终止状态保证只执行一次。终止后保留默认60秒、每数据会话最多4096项的有界墓碑，用来忽略正常竞态产生的迟到帧；墓碑淘汰后的未知data也不能重建请求。

## 2. 取消的具体传播

| 触发 | hub处理 | host处理 | agent影响 |
|---|---|---|---|
| 浏览器请求断开/导航/iframe卸载 | cancel(browser_disconnected)，解除Browser关联 | 取消本机请求context，关闭其body/连接，回cancelled | 不主动调用业务中止接口；最终影响依opencode请求语义 |
| shell退出/会话到期 | 撤销登录，cancel(session_revoked)相关请求/SSE/WS | 同上 | 不删除会话、不停止server |
| 该流下游长期写不动 | cancel(backpressure_timeout) | 关闭本条流 | 不影响同host其他流 |
| opencode进程退出 | 结束浏览器响应或返回502，主机ready=false | 关闭相关上游连接，报告stream-error | 由Supervisor重启server，不能承诺任务保持 |
| host或隧道断开 | 对全部属于旧connId的流失败结束 | 本机取消所有旧connId网络请求 | 不自动重发请求 |
| 用户在opencode点击停止 | 作为普通业务HTTP请求代理 | 原样交给opencode | 由opencode执行业务中止 |

cancelled 默认等待2秒，5秒内强制释放本端资源；无需等待对端响应才停止读写。对端不可达时也必须清理。cancel包含固定reason枚举，不携带用户消息或敏感请求体。

HTTP请求取消和agent任务取消严格按以上职责处理；对PTY而言，连接关闭是否结束本机PTY由opencode决定，首版不另发删除PTY接口。

## 3. 背压

透明HTTP、SSE和WS字节必须在本条流内保持有序、完整；慢消费者通过暂停上游读取传播背压，不能丢掉数据维持表面在线。

1. 每个lane使用C3的256 KiB窗口，接收端默认最多512 KiB缓冲，base64/JSON内存计入总预算。
2. 接收端无法写入浏览器/本机socket时停止扩大该lane窗口；发送端耗尽窗口后停止读取上游body/socket。
3. 不持有整个host或全局writer锁等待窗口。request/response或ws-up/ws-down独立控制，上传阻塞不能阻塞下载。
4. WS多路数据writer采用每reqId每轮最多一个≤64 KiB数据块的公平调度，控制帧有预留队列；不允许持续SSE挤掉审批POST。QUIC使用请求独立stream和同样的有界缓存。
5. WS数据连接本身仍有TCP队首阻塞，公平调度不能消除网络级阻塞。
6. 内存不足先拒绝新流；已接收的流暂停读取，若持续无法推进达到写阻塞期限则取消该流。不允许无界队列，不允许静默丢payload。

## 4. 初始默认配置

以下值供实现起步，必须通过实际负载验证；不是SLA。

| 参数 | 初始默认值 | 行为 |
|---|---|---|
| 单个decoded数据块 | 64 KiB | 实际有少量数据即发，不等凑满 |
| 单帧wire JSON | 256 KiB | 越界帧拒收 |
| 单组HTTP头 | 64 KiB、200个字段值 | 入站越界431；本机响应越界502 |
| 透明请求体上限 | 64 MiB，可配置 | 已知Content-Length超限先413；未知长度超限取消本机上传 |
| 每lane初始窗口/缓冲上限 | 256 KiB / 512 KiB | 连续字节与有界队列 |
| 每host活跃透明请求 | 128 | 包含普通HTTP/SSE/WS；超额429 |
| 单hub活跃透明请求 | 1024 | 总预算兜底，超额429 |
| 每数据会话/单hub流缓冲预算 | 64 MiB / 256 MiB | 包括队列及编码开销；缺额度不接受更多body字节 |
| 本机TCP连接超时 | 10秒 | 头提交前502/504 |
| 普通HTTP响应头等待 | 30分钟，可配置 | 兼容长同步agent请求；活跃配额限制资源占用 |
| WS握手超时 | 10秒 | 101前504 |
| 普通HTTP响应总时长 | 不设固定总期限 | 用户/连接/认证取消仍有效 |
| SSE/WS空闲读取期限 | 不设统一期限 | 安静不是失败，不注入业务心跳 |
| 有待写数据时的写阻塞期限 | 60秒 | 持续无进度取消本条流；不是SSE无事件期限 |
| 隧道连接心跳 | 每15秒探活，45秒未确认判失联 | 底层保活，不能写进opencode业务字节 |
| WS单侧EOF收尾 | 5秒 | 到期关闭两侧 |
| cancel确认/强制清理 | 2秒 / 5秒 | 幂等取消 |
| 浏览器会话绝对期限 | 8小时 | 已开SSE/WS也在期限关闭 |

若请求体在分块上传中才超过上限，本机已经收到部分数据；取消和413不能保证后端完全没有副作用。若已有最终浏览器响应提交，则只能中断响应，不能再写413。

## 5. 错误状态和失败隔离

| 情况 | 最终响应尚未提交 | 最终响应已提交 |
|---|---|---|
| 本机不可达/握手非法 | 502 | 异常断开/reset |
| 连接/响应头等待超时 | 504 | 异常断开/reset |
| host不在线/未ready/能力不支持 | 503 | 异常断开/reset |
| 配额不足 | 429，可带Retry-After | 既有流按背压处理，不能改已提交状态 |
| 上传太大 | 413 | 取消并异常断开/reset |
| 身份过期/被撤销 | 401或导航到网关过期说明页 | 取消并断开已开SSE/WS |
| opencode实际返回4xx/5xx | 原状态/头/体透传 | 按原正常HTTP响应完成 |

单条reqId的非法状态/offset使该隧道失败。长度前缀超限、JSON无法解析、身份不匹配或持续协议滥用会关闭透明数据会话，避免继续消耗资源；不要把此类不可信字节送给LocalProxy。控制鉴权失效时附属连接也应关闭。

## 6. 断线、重连与数据真实性

- host使用已有QUIC优先、WS降级及退避策略建立新连接；成功后重新认证/协商，登记新的数据connId。
- 旧connId上的HTTP/SSE/WS全部失败并清理；任何未结束帧都不能迁移到新connId。
- HTTP隧道不做自动重放，包括GET；上层可以按自身规则重新查询。对POST不能从“没收到响应”推出“没执行”。
- SSE由官方前端重建连接；Last-Event-ID如果原前端使用则当普通头透传。是否补齐期间事件由opencode能力决定。共享库既不解析event id也不承诺opencode事件不丢，前端须能重新读取持久会话状态。
- WS重建需前端重新连接，PTY一次性连接票据是否要重新取得由官方前端决定。旧终端字节不会补发。
- 透明隧道断线不重放请求，不能据此推导OpenCode流具有重放保障。

## 7. Supervisor生命周期

启动：配置固定loopback地址、私有端口、工作目录、Basic凭证；启动opencode serve并在默认30秒内健康检查。超时/子进程退出先结束本次受监管进程、等待回收，再重试；禁止“启动失败但留着无人监管的进程”。健康检查携带本机Basic。

运行：子进程退出使ready=false，结束依赖它的透明请求。指数退避1/2/4/8/16秒重启，5分钟最多5次；超出进入failed，host可以保持管理连接并向hub报告未就绪，等待用户修复。进程持续稳定5分钟后重启计数重置。多host的连接策略与Supervisor的进程重启策略是不同状态机。

退出：停止接收新请求，取消网络流，终止子进程及其进程树，等待回收。Windows使用已有受监管Job Object方案。host不依靠网络取消去清理整个进程。
